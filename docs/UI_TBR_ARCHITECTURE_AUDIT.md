# UI.TBR01 — Window and toolbar architecture audit

Baseline: `dev/ui-native-toolbar`, before the UI.TBR runtime refactor. This is a source audit, not evidence of interactive macOS verification. The app targets macOS 26 through Swift Package Manager.

## Entry points and ownership

| Area | Existing entry point | Behaviour and disposition |
| --- | --- | --- |
| Main scene | `Sources/noema/NoemaApp.swift`, `NoemaApp.body` | Singleton `Window("Noema", id: "main")`, one app-owned `AppModel`, hidden titlebar, 1280 × 820 default, 960 × 620 content minimum. Replace hidden chrome and separate welcome/workspace sizing; preserve the singleton scene and model. |
| Main content | `Sources/noema/ContentView.swift`, `body` | Chooses locked view, welcome, or three-pane workspace from `isLocked` / `isVaultAvailable`. Removes native title and sidebar-toggle toolbar items, extends the workspace into the top safe area. Replace these window-level overrides when native chrome owns layout. |
| Traffic lights | `Sources/noema/TrafficLightEnforcer.swift`, `Probe` / `apply` | Reapplies titled/closable/miniaturizable/resizable/full-size style masks, transparent hidden titlebar, and visible standard buttons on mount, update, key, resize and expose. There are no custom button coordinates. Remove the enforcer after native ownership is established; do not add coordinate positioning. |
| Toolbar-like actions | `ContentView.headerActions`, `inspectorToolbarToggle` | Custom content `HStack` reused in source-library, other library, empty detail and page headers, through `.safeAreaBar` and `pageHeader`. Contains document editing actions, creation/import and vault menu actions alongside inspector visibility. Move global controls to one native toolbar; preserve document-specific actions and existing model operations. |
| Sidebar/search | `ContentView.sidebar`, `switchSidebarScope`, `searchFocused` | Branded sidebar and search field bound to `model.searchText`; `searchFocusToken` requests focus. Sidebar tabs call `model.changeScope`, avoiding animation of the heavy workspace. Preserve sidebar content/search implementation; toolbar search should reveal the sidebar and focus this field. |
| Pane sizing | `ContentView.body`, `InspectorContainer.body`, `InspectorState` | `HSplitView`: sidebar 250/265/280 pt; center minimum 420 pt, or 520 pt for Sources library; inspector 280/340/420 pt and mounted only for inspectable context plus visible preference. Center/inspector disable inherited animation. Preserve independent widths and stable document/table layout; add independent sidebar collapse and persisted visibility. Evaluate split-view replacement against these constraints. |
| Inspector state | `InspectorState`, `InspectorContext.resolve`, `ContentView.resetLocalWorkspaceState` | Local observable visibility and contextual tab/cache state. Session/root changes clear transient targets and caches, while `resetForSessionChange` retains visibility. Preserve that distinction when persisting pane preferences. Inspector content is outside this refactor. |
| Titles | `NoemaApp` scene title; `ContentView.pageHeader` / title fields; `AppModel.title`, `vaultName`, `scopeTitle` | Main title remains static Noema and is hidden. Page/source headings and editable title remain in document content. Add a derived contextual native title from current state; keep the document heading and editing binding stable. No content reads are necessary to derive identity. |
| Restoration | `NoemaApp` scene `.task`; `AppModel.restore` / `remember` | Restores `vaultBookmark` and reopens through `AppModel.open`; no explicit main frame autosave or pane-width/visibility persistence exists in source. Preserve security-scope/bookmark restoration and add presentation-only geometry restoration around it. |
| App/menu actions | `NoemaApp.commands`, `AppModel` methods | Menu commands call the existing model; availability uses `isVaultAvailable`, `busy`, locked state and selected document. Toolbar/menu counterparts should share the same action and availability path. Existing source has no navigation-history API; any back/forward state must respect model selection/save paths. |
| Activation/termination | `NoemaApp.AppDelegate` | Resigning activation saves; reactivation updates view history and schedules refresh; termination flushes edits/titles, preserves recovery failure handling and closes source readers. Preserve these hooks. Window chrome must not introduce another lifecycle controller. |
| Auxiliary windows | `NoemaApp` About/Settings scenes; `NoemaAbout.AboutWindowConstraints` | About is 660 × 560 with native titlebar and deliberate resize/full-screen restriction; Settings has its own theme. Scope main-window chrome/sizing changes to the main scene. |
| Source reader windows | `SourceReader.open`, `updateTitle`, `windowWillClose`, `closeAll` | Separate titled 760 × 600 AppKit windows, keyed by source UUID, with validated content access and temporary-preview/security-scope cleanup. Preserve native chrome, title propagation and cleanup; exclude them from main frame restoration. |
| Editor suggestion panel | `BlockCommands.BlockSuggestionPanel` | Borderless nonactivating child panel positioned from the editor caret; dismisses on parent close/move/resize. Preserve focus behaviour and geometry conversion when titlebar insets change. |
| Modal windows/sheets | `ContentView` sheet/alert bindings, `VaultCreationSheet`, `AppModel.presentPanel` | Model-backed sheets are generally gated by vault availability. File panels attach to key/main/first visible window or present independently. Preserve lifecycle gates and modal ownership; a source reader or About can be the key window. |

## Contracts and risks for implementation

- **D01/D02:** `AppModel.isVaultAvailable` requires `.open`, matching central access-gate state and active lease, plus loaded root/repository. A non-nil root alone is insufficient. Retain storage/session interfaces, command guards, save-before-navigation, admitted-operation draining and stale-result checks. Closed/opening/locking/locked/unlocking presentation must not obtain protected content to populate a title or enable an action.
- **Resizing:** a visible inspector implies at least 950 pt of pane minimums for documents, or 1050 pt for Sources, before dividers/chrome. The existing 960 pt scene minimum cannot fit all Sources pane minimums. Collapse or adjust minimums predictably, retain a usable center, and preserve the user's inspector preference when no target is inspectable.
- **Sources:** retain `SourcesLibraryView`'s native table, `SourcesTablePresentation` and metadata/status observation bridges. They keep table evaluation away from decoded bodies and processing collections. Pane toggles must not rebuild presentation state, animate table switches, or add source decoding to toolbar/title evaluation.
- **Full screen/titlebar:** hidden titlebar, full-size content, ignored top safe areas and custom top padding currently cooperate. Removing only one creates overlap or excess inset. Retire overrides together; validate toolbar compression, traffic lights, sheet placement, zoom and entering/exiting full screen. The enforcer's observers are removed on remount, but it has no explicit dismantle cleanup.
- **State restoration:** welcome needs approximately 680 × 480 pt rather than the current workspace minimum. Keep a stored working frame separate from welcome sizing, clamp restored geometry to the current display, and avoid overwriting it during transient lifecycle states or full screen. Do not reopen a vault twice through competing scene/geometry restore hooks.
- **Multi-window:** this is one workspace window plus About, Settings, source-reader windows and a transient editor panel. Avoid process-global `NSApp.keyWindow` mutation for titles, toolbar or main-frame persistence: another window can own focus. A future `WindowGroup` would require an explicit decision about per-window selection/model ownership; it is not part of this refactor.
- **Titles and accessibility:** native identity must follow welcome, page, source, library and locked state without retaining a prior document title after lock. Truncate long identity labels, keep full accessible names, preserve editor heading geometry, expose control labels/shortcuts and selected pane state, and test keyboard focus when revealing search or collapsing panes.

## Validation handoff
