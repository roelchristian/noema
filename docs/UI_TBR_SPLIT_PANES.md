# UI.TBR04 — Workspace split panes

The workspace retains `HSplitView`. `NavigationSplitView` would introduce navigation-column and selection semantics around a center that alternates between a native Sources table, page library and document editor. Independent inspector visibility would still require another container. Keeping the existing native split avoids changing the Sources presentation bridge, table selection, or document identity for this window-chrome refactor.

`WorkspacePaneState` persists sidebar and inspector intent separately from effective presentation. Context availability and narrow windows can suppress a pane without changing the stored choice. Widening the window restores requested panes. Search requests prioritize and mount the sidebar before focusing its existing search field. Explicit inspector requests prioritize the inspector when only one outer pane fits. Inspector session resets clear caches and tabs while retaining visibility and widths.

The center keeps its existing 420 pt document / 520 pt Sources library minimum. The sidebar has a 190 pt minimum (265 pt initial, 320 pt maximum), allowing sidebar search and the 520 pt Sources canvas to fit the 720 pt workspace minimum. The inspector retains 280/340/420 pt sizing. The native toolbar and View menu can share `FocusedValues.workspacePaneActions`; those actions report effective visibility, and their availability follows vault and inspector context access.

Native `NSSplitView` handles divider dragging. A background probe preserves SwiftUI's split delegate, assigns the center the lowest holding priority, and restores stored outer-pane widths through native `setPosition` only when the pane arrangement or center minimum changes. It records widths only from native divider resize notifications during mouse dragging, so resizing a small window does not replace a user's wider pane preference. It does not add a custom drag gesture, drive every geometry change, animate document/table layout, or alter window frames. Inspector content now respects the native toolbar's top safe area.

Automated coverage uses isolated `UserDefaults` suites for visibility/session retention, Sources minimum-width presentation, automatic collapse/restoration, search priority, divider thresholds, and invalid/restored widths. Interactive verification remains necessary for divider dragging, launch width restoration, full-screen transitions, mounted search focus, and VoiceOver; see the integrated UI.TBR08 report.
