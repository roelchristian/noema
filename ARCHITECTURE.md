# Extending noema

## Where things live

**VaultCore** is independent of SwiftUI. `FileVaultRepository` owns canonical files and coordinated writes. Trash is a sidebar scope backed directly by `.Trash` Markdown files, outside the derived search index. Repository operations list, restore, and permanently delete these files under coordinated access, checking content hashes and path containment. Restore moves bytes to an available Wiki path and rejects active UUID/title collisions; no vault schema change is required. `NoteCodec` handles lossless Markdown bodies and frontmatter. `BlockDocument` and `BlockDocumentCodec` represent rich block trees and their compatible Markdown/JSON envelope; `BlockMutation` owns structural operations independently of AppKit. `MarkdownService` analyzes links/tags and produces a Sendable preview model. `SQLiteSearchIndex` maintains rebuildable search/tag/backlink tables. `RecoveryStore` journals unsaved drafts outside the synced folder.

**noema** owns the UI. `AppModel` runs on the main actor; storage/index work runs in separate actors, and parsing runs in detached tasks. `ContentView` arranges navigation and pages. `NativeTextViews` bridges read-only source text and attributed source previews. `RichArticleView` bridges the article editor; `BlockEditorCoordinator` synchronizes its value document with one native `ArticleTextView`, manages selection/commands and the shared undo manager, and publishes the complete body to the existing draft/autosave path. `BlockTextStorage` renders/captures rich runs without flattening collapsed descendants. `BlockCommands` owns slash matching/presentation and a nonactivating native suggestion panel constrained above or below the caret within the visible editor; `SemanticRegistry` owns semantic icons, accessible names, and optional statuses. Native drag sessions carry document-scoped block IDs and reorder sibling subtrees; explicit indent/outdent commands change parentage. `VaultWatcher` forwards file-presenter and recursive FSEvents notifications into debounced reconciliation, including changes from editors that do not coordinate their writes.

The `VaultRepository` and `SearchIndex` protocols are the seams for replacing storage/index implementations. Keep UI actions out of codecs, and keep filesystem work out of view bodies. SQLite connections are confined to their index actor.

## Identity and evolution

New wiki pages and sources get UUIDs. A plain external Markdown page gets a deterministic temporary identity derived from vault UUID and relative path; that identity is persisted on first app save. Moving such a page externally before its first save changes its temporary identity. Persisted IDs survive moves. App title changes add aliases and retain stable filenames.

Vault manifests have an explicit format version. Reject unsupported versions instead of silently rewriting data. Preserve unknown frontmatter fields for future extensions. Canonical knowledge lives in files; caches and derived data can always be rebuilt. Page bodies remain readable Markdown. Edited block documents add an independently versioned JSON envelope in a trailing HTML comment, guarded by a checksum of the readable body. No sidecar is required. External text wins over stale metadata; the old payload remains recoverable. Future envelope versions are read-only, while vault format stays at version 1. Search, tags, word count, and previews omit the metadata envelope. See `BLOCK_EDITOR.md` for compatibility details. UI colors are dynamic AppKit semantic colors; brand colors are used only by identity artwork.

## Later milestones

- **Provenance:** add source UUID references to wiki metadata and a source/page relationship view. Keep raw imports immutable and make relationships many-to-many. Existing source IDs and checksums provide identity and revision tracking.
- **Semantic retrieval:** derive heading-based sections with note/source UUID, heading path, content hash, and text. Store embeddings in local derived storage. Recompute changed sections, and label whether a passage is a source or a personal interpretation.
- **LLM context:** retrieve relevant passages, then apply the selected model’s tokenizer and context budget. Include compact identity/provenance metadata; do not replace the original text with a model’s token stream or generated summary.
- **Additional importers:** put PDF/web extraction behind an importer service; retain the original and treat extracted text as derived content. Extend source schema deliberately.
- **Mobile:** share VaultCore, build a separate UI, and test coordinated edits across platforms before claiming sync compatibility.

Start with one extension at a time. There is no server, remote AI provider, vector store, or runtime plugin system in v1. `OnDeviceSummary` uses Apple Foundation Models asynchronously in a dedicated actor. Summaries use existing semantic block metadata (`summary`, `extra.aiGenerated`) without a schema version change. The native SwiftUI summary is rendered above the editable document; the binding retains it across edits. Generation only applies to the same unchanged, unlocked page and vault.
