# Extending noema

## Where things live

The Semantic Blocks library scope derives searchable block rows from page snapshots off the main actor, without a persisted index or schema change. It searches semantic metadata, block text, and owning page titles, omitting generated AI summaries. Selection uses the existing save-before-navigation path and block editor action; ContentView reuses the same article detail and page inspector as Pages. Current editor content is included in search snapshots and debounced edits refresh results.

**VaultCore** is independent of SwiftUI. `FileVaultRepository` owns canonical files and coordinated writes. Trash is a sidebar scope backed directly by `Removed Pages` Markdown files, outside the derived search index. Repository operations list, restore, and permanently delete these files under coordinated access, checking content hashes and path containment. Restore moves bytes to an available Wiki path and rejects active UUID/title collisions; no vault schema change is required. `NoteCodec` handles lossless Markdown bodies and frontmatter. `BlockDocument` and `BlockDocumentCodec` represent rich block trees (including inline math and display math blocks) and their compatible Markdown/JSON envelope; `BlockMutation` owns structural operations independently of AppKit. `TeXMath`, `TeXMacro`, and `TeXMacroStore` parse and expand custom `\newcommand` macros (with 0 to 3 arguments) and render TeX expressions for inline and display math. `MarkdownService` analyzes links/tags (excluding code and math) and produces a Sendable preview model. `SQLiteSearchIndex` maintains rebuildable search/tag/backlink tables. `RecoveryStore` journals unsaved drafts outside the synced folder.

**noema** owns the UI. `AppModel` runs on the main actor; storage/index work runs in separate actors, and parsing runs in detached tasks. `ContentView` arranges navigation and pages. `NativeTextViews` bridges read-only source text and attributed source previews. `RichArticleView` bridges the article editor; `BlockEditorCoordinator` synchronizes its value document with one native `ArticleTextView`, manages selection/commands and the shared undo manager, and publishes the complete body to the existing draft/autosave path. `BlockTextStorage` renders/captures rich runs without flattening collapsed descendants. `BlockCommands` owns slash matching/presentation and a nonactivating native suggestion panel constrained above or below the caret within the visible editor; `SemanticRegistry` owns semantic icons, accessible names, and optional statuses. Native drag sessions carry document-scoped block IDs and reorder sibling subtrees; explicit indent/outdent commands change parentage. `VaultWatcher` forwards file-presenter and recursive FSEvents notifications into debounced reconciliation, including changes from editors that do not coordinate their writes.

The `VaultRepository` and `SearchIndex` protocols are the seams for replacing storage/index implementations. Keep UI actions out of codecs, and keep filesystem work out of view bodies. SQLite connections are confined to their index actor.

`VaultContentStore` defines a lower-level vault-owned byte boundary. `PlaintextVaultContentStore` scopes root access per synchronous operation, validates relative paths and rejects symlink ancestry again inside NSFileCoordinator access, and atomically writes unchanged plaintext. Writes require create-only or expected-byte replacement; moves/deletes require a current file or flat source-directory snapshot and reject unresolved cloud versions. Preconditions and mutations share one coordination window; separate calls are not a transaction, and arbitrary uncoordinated filesystem writers remain outside that guarantee. Missing cloud bytes request hydration and report unavailable. Typed errors leave recovery/conflict preservation policy with the repository. Wiki creation, scan cache misses, saves, trashed-page reads, and preserved conflict copies use this adapter. Source original/metadata reads, metadata updates, staged publication, and source trash/restore/deletion also use it. Source staging directories use coordinated create-only directory creation; publication requires the exact expected original/metadata snapshot. Imported reader and availability reads use the same byte seam, while external linked files retain separate bookmark-scoped coordinated reads. Directory snapshots refuse conflicted children, and source mutations recheck expected bytes inside coordination. The repository retains NoteCodec, identity/alias validation, content hashes, scan caching, and cloud-version preservation policy; expected-byte replacement catches changes between the initial read and coordinated write. Manifest reads/create-only writes, structural directory creation, page trash/restore/permanent deletion, legacy trash migration, and retention ledger reads/expected-byte writes also use the adapter. A competing retention ledger write aborts expiration before any deletion. New-vault staging initializes canonical contents through the same repository/adapter; its parent-folder staging creation, publication move, and failed-staging cleanup remain separate because they are outside the eventual vault root. Discovery/enumeration, resource probes, provider hydration, and OS-owned conflict-version reads/resolution remain repository responsibilities. RecoveryStore and SQLiteSearchIndex remain separate app-local stores. RecoveryStore atomically journals unsaved JSON and removes it only through existing explicit lifecycle actions; a corrupt JSON draft currently fails listing without deleting any drafts. SQLiteSearchIndex owns its connection and WAL/SHM lifecycle inside its actor; its database is derived and rebuildable. Neither store belongs in the canonical content adapter. No file format, external linked-file access, recovery journal, or index boundary changes.

Linked sources use optional `linkedBookmark` data in source metadata (vault format remains v1). The bookmark is generated with `securityScopeAllowOnlyReadAccess`; repository scanning resolves it and reads the external original under coordinated access, releasing the security scope afterward. These records have metadata only, with no in-vault original; the checksum records capture-time bytes, while subsequent linked reads accept external changes. Existing imported records retain checksum enforcement. File imports enforce a 2,000,000-byte maximum in the repository as well as the picker. UTF-8 text/Markdown/HTML provide searchable bodies; binary originals have empty derived text and retain byte checksums. Older app versions cannot read binary sources. Folder additions are rejected; the picker accepts at most five files per batch and rejects an excessive selection before creating records. Existing records from past folder additions remain readable. Before publication, repository additions inspect existing metadata under coordinated reads and reject matching original checksums across source modes or the same resolved linked file path. AppModel catches each selected file independently and accumulates named failures while continuing the batch. No filename-only match or persisted schema change is introduced. External files are never written by this path. Bookmarks are machine/app-specific; earlier app versions report linked records as unavailable rather than modifying them. Valid linked metadata remains visible with an empty derived body and transient availability issue when its original cannot be read. On-demand availability checks use coordinated reads and security scopes off the main actor, verify imported checksums, and never write source metadata. AppModel owns a serial queue and session-only results, cleared on vault switching. Refresh reloads linked content; the vault watcher does not watch external paths. Sources uses a navigation sidebar and table, with a resizable metadata/AI-summary inspector to the right when a row is selected. Selection is local UI state; double-click and Open Preview retain the separate native reader behavior. `SourceReader` owns native read-only NSTextView or QLPreviewView windows, retains security scope for their lifetime, and releases it when closed. Reader loading verifies in-vault checksums and uses coordinated reads off the main actor.

Source metadata optionally records `aiSummary` and `fileSize`, derived from canonical bytes during scanning for older records. `AppModel` owns a single serial source-title queue, exposes pending row IDs and completed/total progress, and clears pending work on vault changes. Files are published in the table before inference. Text/HTML/Markdown and PDFKit-extracted PDF text feed the existing on-device topic-title generator. Source inference uses the exact article `pageTitle` method and the same block-document normalization; HTML markup is stripped before normalization. For each queued file, separate on-device sessions generate the article-rule topic title and a concise summary concurrently from the same extracted content (at most the first 6,000 characters). Both results persist in one coordinated metadata write; empty summaries and stale prior summaries reject the write. Manual renames preserve the existing summary. No summary is rendered in the table; legacy metadata without `aiSummary` remains readable. The context menu and metadata inspector expose manual Generate/Regenerate AI Summary actions using the same off-main-actor text extraction. Per-source progress disables duplicate requests, vault generation tokens discard earlier-vault results, and coordinated metadata writes preserve the display title and reject stale summaries/renames/deletions. Existing summaries remain visible until replacement succeeds. Context-menu rename changes only metadata and suppresses the queued AI result. Source deletion coordinates the UUID directory, rejects stale metadata, mutated imported bytes, symlinked directories/metadata, and unresolved conflicts. Linked deletions remove only vault records; imported deletions move the stored original and metadata to recoverable trash after explicit confirmation. Neither path recreates a deleted record. Repository title updates coordinate metadata writes, reject stale identity/title/checksum/bookmark/path values, and preserve original names and bytes. Queue errors retain original titles and surface a notice. Search is reconciled after successful renames. No persisted AI provider integration or physical original-file rename is introduced.

Source-to-page AI creation reuses source text extraction and the on-device model actor. AppModel tracks in-flight source IDs and vault generation tokens, saves the current editor before navigation, and opens the generated article for editing. The repository creates the page and its initial source UUID reference in one coordinated page write after checking the source still exists and its captured content matches; no intermediate unlinked page is published.

Page provenance is stored as a `sources` UUID sequence in wiki frontmatter; absent fields mean no references. Both inspectors derive their many-to-many relationship from pages. Repository updates use existing coordinated, stale-checked page saves, preserve bodies/original source bytes, and reject locked pages. Vault format remains v1; older versions preserve this field as unknown YAML but do not expose it. Deleted/unavailable sources retain their UUID references until explicitly removed.

## Identity and evolution

Vault creation uses an application-owned SwiftUI sheet; NSOpenPanel selects only an existing parent. AppModel retains security-scoped parent access through off-main-actor creation and opening/bookmarking the child. FileVaultRepository.createNewVault validates the name and parent capabilities, stages the complete v1 plaintext structure beside its destination, and publishes it by a coordinated same-parent move without merging an occupied folder. Failed publication removes staging. Encryption intent stays transient: UI, AppModel, and repository gates reject encrypted requests before creation. The setup sheet exposes encryption as a disabled, off-state future capability and offers only explicitly confirmed plaintext creation; it performs no biometric probing. No authentication, recovery keys, encryption metadata, or protected indexing is implemented. Encryption remains unavailable until those facilities are implemented and tested together.

Trash storage uses the ordinary `Removed Pages` directory rather than the externally cleared `.Trash` name. Trash combines pages and source records without tabs. Source deletion moves the entire UUID directory to a collision-safe `.source` directory in Removed Pages using coordinated moves. Restore preserves identity and bytes, rejects occupied identities and duplicate sources, and stale snapshots or unsafe/conflicted directories block restore/deletion. Linked originals are never touched. Timestamped trash filenames and a coordinated `Trash Retention.json` ledger track a 15-day retention period; existing undated entries receive a full grace period at first refresh. AppModel expires trash on refresh/open through the same snapshot-checked permanent deletion operations, preserving damaged/unreadable/conflicted entries and reporting failures. Cleanup waits while the app is closed. Canonical v1 page/source formats are unchanged; older builds cannot display trashed sources. Enumeration migrates any surviving legacy `.Trash` Markdown files with coordinated moves, collision-safe destination names, and no content rewrite; failed migrations retain their legacy entry with an issue. Page deletion coordinates both source and destination as a move, and both trash and restore announce the new URL to file presenters. The v1 manifest/Markdown formats are unchanged; older builds cannot display the new trash location. Trash enumeration isolates per-file failures: `TrashedPage` carries a read issue and retains the raw-byte hash when decoding fails, so damaged Markdown remains visible and can be safely deleted but cannot be restored until repaired. Unreadable or unsafe paths cannot be deleted. Bulk emptying accepts the confirmed page snapshots and applies the same coordinated hash/conflict/path checks to each, returning individual failures while processing other items. AppModel serializes trash actions, guards vault-generation changes, reloads the trash list after operations, and refreshes the derived page/search state. No persisted format changes.

New wiki pages and sources get UUIDs. A plain external Markdown page gets a deterministic temporary identity derived from vault UUID and relative path; that identity is persisted on first app save. Moving such a page externally before its first save changes its temporary identity. Persisted IDs survive moves. App title changes add aliases and retain stable filenames.

Vault manifests have an explicit format version. Reject unsupported versions instead of silently rewriting data. Preserve unknown frontmatter fields for future extensions. Canonical knowledge lives in files; caches and derived data can always be rebuilt. Page bodies remain readable Markdown. Edited block documents add an independently versioned JSON envelope in a trailing HTML comment, guarded by a checksum of the readable body. No sidecar is required. External text wins over stale metadata; the old payload remains recoverable. Future envelope versions are read-only, while vault format stays at version 1. Search, tags, word count, and previews omit the metadata envelope. See `BLOCK_EDITOR.md` for compatibility details. The NoemaTheme environment maps shared NoemaBrand palette roles to UI colors. Persisted `noema.theme` and `noema.theme.fullPalette` defaults select System or a light/dark palette, applied throughout the app or as an accent only. System and accent-only surfaces use dynamic AppKit semantic colors. Native selection and focus remain platform-managed; theme changes rerender attributed editor content without resetting selection or undo. Identity exports retain the default Midnight Iris tokens. The native theme dropdown uses shared, observable main-actor ThemePreviewState for transient highlights. Theme modifiers prefer this preview over persisted defaults; closing the menu commits only an explicit selection and otherwise restores the stored preference.

## Later milestones

- **Semantic retrieval:** derive heading-based sections with note/source UUID, heading path, content hash, and text. Store embeddings in local derived storage. Recompute changed sections, and label whether a passage is a source or a personal interpretation.
- **LLM context:** retrieve relevant passages, then apply the selected model’s tokenizer and context budget. Include compact identity/provenance metadata; do not replace the original text with a model’s token stream or generated summary.
- **Additional importers:** put PDF/web extraction behind an importer service; retain the original and treat extracted text as derived content. Extend source schema deliberately.
- **Mobile:** share VaultCore, build a separate UI, and test coordinated edits across platforms before claiming sync compatibility.

Start with one extension at a time. There is no server, remote AI provider, vector store, or runtime plugin system in v1. `OnDeviceSummary` uses Apple Foundation Models asynchronously in a dedicated actor. Summaries use existing semantic block metadata (`summary`, `extra.aiGenerated`) without a schema version change. The native SwiftUI summary is rendered above the editable document; the binding retains it across edits. Generation only applies to the same unchanged, unlocked page and vault.

Automatic titles share the Foundation Models actor. AppModel tracks newly created placeholder titles in memory and finalizes them at navigation/lifecycle save boundaries, saving content before inference. Per-page background tasks save captured page snapshots through coordinated repository writes without requiring selection or focus. Stale hashes, deleted/locked pages, and changed active editors reject results; quit awaits pending tasks. NaturalLanguage detection chooses the article language with system preference fallback; Foundation Markdown parsing strips output formatting. Results require unchanged vault and page content; normal repository saves retain filenames and aliases. No persisted format changes.

Explicit Save Page (⌘S) and finishing editing register blank/Untitled placeholder pages for naming even after reopening. Other lifecycle triggers retain session-local eligibility.

URL captures use VaultCore WebSourceFetcher for HTTP(S) validation, uncached GET requests, status/type checks, a 20-second request timeout, and a bounded 2 MB response stream. FileVaultRepository publishes original response bytes and metadata through the existing staging/coordinated import path. Optional `isURLSource` and `webAvailabilityIssue` metadata distinguish URL captures from pasted/imported sources with origin links; absent fields preserve existing behavior, vault format remains v1, and older readers ignore the new fields. AppModel imports at most five nonempty lines with independent error handling and feeds successes into the existing on-device naming/summary queue. URL availability checks refetch without changing canonical bytes, title, or summary; coordinated metadata updates persist archived/unavailable status and clear it on recovery. Search/scanning still derives content from the captured original.

The sandboxed app now permits outbound network connections. Its App Transport Security policy permits HTTP for explicitly entered source URLs, alongside HTTPS. No remote AI provider is used; fetched content enters the existing on-device inference path.

Topic-page creation uses VaultCore WebTopicResearch to query Bing's public RSS search, parse ranked HTTP(S) result links, and fetch up to three readable HTML/text pages among the first five using the existing bounded WebSourceFetcher. Off-main-actor async research supplies bounded untrusted text to the on-device model actor. AppModel guards duplicate requests/vault changes and uses save-before-navigation and coordinated page creation. Drafts include numbered web citations, application-supplied result URLs, and a retrieval timestamp. Empty/blocked search or entirely unreadable results fail without publication; there is no general-knowledge fallback. This adds external web search and page fetching, with no remote AI provider or persisted schema change.

Page editing locks use a dedicated repository operation through the existing coordinated, stale-checked save path, preserving `updatedAt` for the lock metadata write. Pending editor content is saved first through the ordinary content save. AppModel serializes saves and suppresses duplicate per-page lock requests, publishing the returned persisted snapshot only after success. Sidebar ordering derives directly from content timestamps, with no presentation holds or delayed move feedback. The optional frontmatter lock field and vault v1 format remain unchanged; editing locks provide accidental-edit prevention, without encryption or authentication.

## Storage adapter replacement contract (D01.6)

See `STORAGE_ACCESS_AUDIT.md` for the final canonical-access inventory and permitted I/O exceptions. The build and test wrappers run `scripts/check-storage-boundary.py`; exceptional access is explicitly reviewed in `scripts/storage-io-exceptions.json`.

A future encrypted implementation would implement `VaultContentStore` and return logical plaintext bytes to the existing codecs/repository. Expected-byte writes and file/directory snapshots must compare logical contents while retaining coordinated physical access, atomic publication, containment/symlink checks, create-only refusal, stale/conflict preservation, hydration errors and file-presenter notifications. It must retain the selected root's security-scoped capability. Separate protocol calls remain separate operations, without an implied transaction.

`VaultStorageProvider` is the explicit construction policy: repository open selects one store (or accepts the existing direct injection), retains it as a nonisolated Sendable dependency, and AppModel passes that same store to readers, availability checks and summary extraction. These consumers require an explicit store and cannot default to plaintext. AppModel retains its provider across vault switches and passes it to new-vault creation; creation selects a store for its temporary staging root, and opening the published root selects a fresh store rather than reusing one bound to the moved staging path. The construction guard permits runtime plaintext adapter construction only in the provider. No singleton or session/authentication state is introduced. Discovery currently sees physical filenames/resource values, so a design that hides names or changes layout also needs a deliberate discovery seam. Imported Quick Look previews receive disposable copies of adapter-validated bytes rather than canonical URLs; reader close, errors and vault switching remove those copies. Linked previews retain external URL/security-scope behavior. Preview copies are plaintext app-local temporary files, so a future encrypted implementation still needs a deliberate confidentiality and interrupted-cleanup policy. OS conflict-version bytes must be interpreted through the chosen format before logical preservation. These are future design requirements, not implemented facilities.

Plaintext v1 remains the only supported format. Any future encryption requires explicit format negotiation and opt-in migration, independent key/recovery design, and a policy for plaintext recovery drafts, SQLite copies/WAL, previews and external originals. It must test existing plaintext/legacy vault compatibility, interrupted publication, stale writes, cloud conflicts and two-Mac synchronization before sign-off. No crypto stubs, key fields, encrypted adapter or claim of at-rest protection is added here.

`VaultSessionManager` in `VaultCore` owns the standalone six-state vault session state machine (`closed`, `opening`, `open`, `locking`, `locked`, `unlocking`), typed transition errors (`VaultSessionError`), session identity (`VaultSession` with vault UUID, canonical root URL, and monotonic `generation`/`epoch`), serialized transitions, duplicate-request coalescing, cancellation rollback, and read-only `AsyncStream<VaultSessionState>` observation independent of `AppModel` and SwiftUI. `VaultAccessGate`, `VaultSessionLease`, `VaultAccessError`, and `GatedVaultContentStore` connect `VaultSessionManager` to the `VaultContentStore` and `FileVaultRepository` boundaries: every protected read and write requires a valid lease matching the active open session's UUID, vault ID, canonical root, and generation, revalidated synchronously when repository actor methods and adapter I/O actually execute (including after async suspension points) so queued or in-flight work crossing a lock or vault-switch boundary is rejected. `VaultLockAdmissionBarrier`, `VaultAdmittedOperation`, `VaultOperationRegistration`, `VaultOperationRegistrySnapshot`, and `VaultOperationAdmissionError` share the gate's atomic lock: transitioning `open → locking` atomically closes the admission barrier to new protected operations while retaining previously admitted operations in the registry, allowing scoped admitted work to finish draining, handling concurrent lock callers, task cancellation, and `deinit`-guarded abandoned registrations without deadlocks or leaks, and awaiting in-flight completion before transitioning to `locked`. `VaultSaveQuiescenceCoordinator`, `VaultQuiescentOperationContext`, `VaultPendingEditorState`, `VaultQuiescenceReport`, and `VaultQuiescenceError` coordinate safe quiescence of in-flight saves, autosaves, LCC metadata updates, and source imports/downloads during `locking`: operations distinguish pre-commit work (which can be cooperatively cancelled, journaling unsaved page edits to `RecoveryStore` and cleaning up `.import-*` staging directories) from the durable commit window (which finishes uninterrupted so committed writes remain recognized), while unrecoverable quiescence or recovery failures abort the lock transition and keep the session in `open` without falsely publishing `locked`. `VaultStaleResultGuard`, `VaultCompletionTicket`, `VaultCompletionKind`, `VaultStaleCompletionReason`, and `VaultStaleCompletionError` validate asynchronous completions against the active session identity (`sessionID`, `vaultID`, `root`), monotonic `generation` epoch, UI generation token, target entity ID, and captured content before publishing search, preview, source loading/availability, indexing/refresh, or AI-processing results into `AppModel`, `SQLiteSearchIndex`, or `SourceReader`, even when cooperative task cancellation is ignored. `FileVaultRepository.inspectManifest(at:contentStore:storageProvider:)` and `FileVaultRepository.preflightOpen(root:create:storageProvider:)` keep `vault.json` manifest and directory safety inspection outside the protected content API so destination vaults are validated before tearing down an active or locked session; if destination preflight fails, the previous vault remains intact, whereas failures after transition begins roll back the new session to the documented recoverable `.closed` state without partial initialization or cross-vault leakage. `RecoveryStore` (`open`, `store`, `remove`, `drafts`), `SQLiteSearchIndex`, `SourceReader` (both imported and linked source reads and window presentation), and `AppModel.sourceSummaryContent` enforce `VaultAccessGate` / `VaultSessionLease` validation, while post-drain recovery draft journaling during lock quiescence executes within a registered quiescence scope. Session locking and leases implement **application-level access revocation and lifecycle isolation**, not cryptographic protection: canonical vault files, app-local SQLite FTS5 indexes, recovery draft JSON files, disposable Quick Look preview files, and external linked originals remain plaintext on disk until Phase 3 cryptographic storage is implemented.

Lifecycle actions in `AppModel` reject overlapping open/lock/unlock/close requests and retain manager failures as typed `sessionTransitionErrors` alongside their UI message. A failed close preserves existing resources; successful close requires the central `.closed` state before resources and bookmarks are discarded. Lock completion verifies the vault identity and generation, and open/unlock publish initialized resources only while their session still owns the gate. Rollback failures are presented with the initialization error and reconcile to the actual central state. State observations ignore obsolete emissions and purge loaded resources when a new open session has a different lease. Coalesced manager close callers await the shared state commit and receive the same typed failure. Recovery construction requires a gate and an explicit valid lease; ungated fixtures use a separate internal initializer.
